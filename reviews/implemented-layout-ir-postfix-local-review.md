- **Blocker (high):** Global `BoundingBox` strictness now makes the PyMuPDF parser fail on valid extractable PDFs whose optional text bbox extends slightly outside the crop box. `_make_bounding_box()` only rejects inverted boxes before constructing `BoundingBox` (`pymupdf.py:158-167`), so negative x/y values from PyMuPDF propagate as a Pydantic `ValidationError` instead of dropping/clamping the optional bbox. I reproduced this with generated PDFs: inserting text at `(72, 5)` produced raw line bbox `(72.0, -6.825..., 97.058..., 8.289...)` and `PyMuPDFParser().parse()` raised `ValidationError`; inserting at `(0, 0)` and `(-10, 72)` also failed. This is a parser regression caused by the stricter IR invariant. The adapter should normalize valid boxes or return `None` for invalid optional text bboxes rather than reject the whole document.

- **Note:** Test coverage for the fixed strictness is close but not complete: the non-finite test uses `inf` only (`test_layout_models.py:219-220`), not `NaN`, though `allow_inf_nan=False` should reject both. Page-bound tests exercise block regions; the shared validator also covers table/cell/figure regions in code (`models.py:641-651`, `674-678`), but those paths are not directly asserted.

**Final verdict:** Change required before treating the postfix as production-ready. The previous reported findings are fixed, but the PyMuPDF bbox/strictness interaction introduces a new high-severity regression.
